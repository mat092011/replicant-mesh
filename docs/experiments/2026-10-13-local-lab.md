# First container simulation: measured smoke experiment

> Historical Replicant Mesh experiment, recorded before the project rename.
> Original image names, source paths and measurements are retained as evidence;
> use the [migration guide](../RENAMING.md) for current commands and names.

On 2026-10-13, three CPU Petals worker containers successfully served the pinned
eight-layer TinyLLama model on one ASUS Vivobook laptop. Numerical and session
checks passed. All 58 measured benchmark requests completed, including eight
simultaneous long-context requests. No failed requests were excluded.

This establishes a working local simulation. It does not establish the utility
of a large model on independent consumer GPUs or the full research phase gates.

## Environment and method

- Ryzen AI 9 HX 370, 12 physical cores / 24 logical CPUs, about 32 GB host RAM.
- Docker Desktop 4.95.0, Engine 29.8.2, Compose 5.6.0, Linux amd64 under WSL2
  kernel 6.6.87.2. Docker exposed 24 logical CPUs and 15.18 GiB RAM.
- `Maykeye/TinyLLama-v0`, revision `298338802ab94432b917bcce11382aa151aee50f`;
  float32, eager attention, no activation compression or weight quantization.
- Petals `22afba627a7eb4fcfe9418c49472c6a51334b8ac`; Python 3.10.16;
  PyTorch 2.3.1+cpu; Transformers 4.43.1.
- Worker ranges `[0,3)`, `[3,6)`, `[6,8)`; each limited to 2 CPUs and 3 GiB RAM.
  Client limited to 2 CPUs and 5 GiB RAM. All share one physical host.
- Client-mediated stage traffic, explicit independent sessions, greedy sampling,
  repeated public fixture, fixed output length with EOS ignored, closed-loop load.
- Model loading and one warm-up request per benchmark excluded from measured
  throughput. Session setup, prefill, token generation, and session closing are
  inside the shared interval. First-token latency includes setup and prefill.

The [machine-readable summary](2026-10-13-local-lab-summary.json) preserves run
names, arguments, loading times, numerical comparisons, and aggregate metrics.
The [package inventory](2026-10-13-runtime-freeze.txt) records resolved versions.
Raw per-request reports, qdisc snapshots, ping output, and resolved Compose
configuration remain in the ignored `.lab/results/` directory.

## Correctness and configuration checks

The image built successfully with `pip check`; all 21 unit tests passed on the
host and inside the image. Compose configuration and PowerShell syntax passed.

Two end-to-end correctness runs each passed eight comparisons using identical
prefill and forced continuation tokens. Maximum absolute logit difference was
**0.0** for these cases; every greedy-token comparison agreed. The declared
tolerance remains provisional at `atol=1e-3, rtol=0`, rather than a calibrated
bound for other models or hardware. Interleaved sessions continued correctly
after another session was closed, a new session started correctly, and input
beyond a declared session limit was rejected. These checks do not measure actual
worker cache reclamation or validate hostile RPC messages.

Logs confirmed all three ranges were loaded and selected in inference routes.
After the initial measurements, bootstrap advertisement was narrowed to the
container interface (excluding loopback); the image was rebuilt, workers
recreated, and correctness rerun successfully before the capacity smoke test.

## Network and throughput results

Five client-to-worker pings measured mean RTT of **0.128 ms** without shaping and
**50.708 ms** with shaping. The WAN preset configured 25 ms outgoing delay and
100 Mbit/s aggregate outgoing rate per worker/client container. `tc` confirmed
those settings; achieved bandwidth was not independently measured. No packet
loss occurred in these ten pings. Shaping was removed and all four interfaces
were verified back at `noqueue` after testing.

Each row below used 10 measured requests, 128 prompt tokens, and 8 output tokens
per request. All rows completed 10/10. Token intervals are pooled across completed
requests. These small samples are smoke results, with unstable tail estimates.

| Execution | Active sessions | Aggregate output tokens/s | First token p50 / p95 (ms) | Token interval p50 / p95 (ms) |
| --- | ---: | ---: | ---: | ---: |
| Complete model, local client | 1 | 522.43 | 4.72 / 7.22 | 1.41 / 1.78 |
| Three stages, unshaped | 1 | 47.05 | 33.40 / 39.74 | 18.06 / 21.60 |
| Three stages, unshaped | 3 | 79.33 | 51.92 / 66.57 | 31.16 / 40.29 |
| Three stages, WAN preset | 1 | 4.76 | 239.40 / 255.33 | 182.65 / 186.66 |
| Three stages, WAN preset | 3 | 12.07 | 205.86 / 351.32 | 184.27 / 192.27 |

An additional unshaped capacity smoke run completed **8/8 concurrent requests**,
each with 1,024 prompt tokens and 64 output tokens. It produced 512 tokens in
12.197 seconds: 41.98 aggregate tokens/s, 2.757 s median first-token latency,
and 125 ms median token interval. Its different workload prevents direct comparison
with the table above. It is a successful admission/completion test, not a numerical
correctness check for long contexts.

Concurrent sessions increased aggregate throughput in this run, while ordinary
single-request generation remained sequential. The complete model was much faster
on this tiny workload; transport overhead dominates its small compute requirement.
The reference and pipeline have different aggregate CPU quotas, so this is a
comparison of configured prototypes, not a resource-normalized speedup claim.

## Remaining evidence and reproduction

An idle snapshot after the final benchmark showed approximately 524, 529, and
515 MiB in the three worker containers, and 353 MiB in discovery. These are
snapshots, not peaks; the client benchmark process had already exited. Peak
memory, stage overlap, retry counts, compute/queue/transfer breakdowns, real WAN
links, energy, larger models, and failure recovery remain unmeasured.

Follow [LOCAL_LAB.md](../LOCAL_LAB.md) to build, launch, check, and reproduce the
short runs. Add the single-session WAN comparison with:

```powershell
docker.exe compose exec -T client python -m lab.benchmark bench --concurrency 1 --label wan-c1
```

The capacity smoke command, under the unshaped profile, was:

```powershell
docker.exe compose exec -T client python -m lab.benchmark bench --concurrency 8 --requests 8 --prompt-tokens 1024 --new-tokens 64 --label capacity-smoke
```

Before claiming a performance envelope, collect repeated larger samples, isolate
delay and bandwidth effects, add resource-matched controls, and instrument the
workers. The optional BLOOM configuration has not been run.
