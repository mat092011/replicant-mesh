# Owned PyTorch runtime: M0/M1 validation

Date: 2026-10-14. This is an implementation correctness experiment on one laptop.
The M0 configuration/import gate and M1 in-process parity gate passed. This does
not establish network performance, useful pipeline overlap or pooled-memory benefit.

Machine and source: AMD Ryzen AI 9 HX 370, approximately 32 GiB host RAM,
Docker Desktop Linux/amd64 under WSL2, Docker Engine 29.8.2, Compose 5.6.0 and
approximately 15.18 GiB Docker VM RAM. Test and benchmark containers had two CPU
cores of quota, two Torch threads and a 6 GiB memory limit. Historical Petals
containers remained running; host contention and thermals were not controlled.
The implementation started from `650489d06f2dd4ee96254b88e3cc5db2601be4e9`.
File hashes, versions, numerical observations, fixtures, smoke attempts and the
failed-run record are in the [JSON evidence](2026-10-14-pytorch-m1-summary.json).

## Fixed setup

The checkpoint/tokenizer is `Maykeye/TinyLLama-v0` revision
`298338802ab94432b917bcce11382aa151aee50f`. Preparation verifies the seven source
hashes, creates float32 slices for `[0,3)`, `[3,6)`, `[6,8)` and the coordinator
input/output components, and validates the generated manifest. Its fingerprint is
`33aec5e084dc12cef677821fcc8ca55a00f74298531f1a97d499658e6930254d`.

The complete reference and all partitions use Python 3.12.15, PyTorch 2.14.1+cpu,
Transformers 5.19.0, CPU float32, eager attention and no activation compression.
The new image also pins gRPC 1.84.0 and Protobuf 7.36.2 for later protocol work;
neither transport nor RPC workers are implemented in M1. All 38 application
dependencies have exact wheel URLs and SHA256 hashes. The base image is pinned
by its Linux amd64 digest; see [the environment record](../../docker/pytorch/README.md).
Environment verification confirmed Petals, Hivemind and bitsandbytes were absent.

## Results

| Check | Observation |
| --- | --- |
| Complete Compose suite | 49 tests passed; no failures or skips |
| Full prefill logits | Every vocabulary logit at each of 1/128/1,024 input positions agreed within tolerance |
| Forced continuation | Eight identical forced tokens after each prompt length passed |
| All recorded numerical comparisons | 44 comparisons, largest absolute difference `1.9073486328125e-6` |
| Acceptance tolerance | Frozen beforehand at `atol=1e-3`, `rtol=0`; unchanged |
| Greedy generation | Both 16-token sequences matched independently generated reference sequences |
| Cache/session lifecycle | Interleaving, context overflow rejection, eight-session admission, close and injected compute failure passed |
| Final live cache state | Zero active sessions, reserved positions and allocated cache tensor bytes |
| Short benchmark CLI correctness check | Eight comparisons passed with maximum difference zero |
| Legacy Petals regression | Eight existing correctness comparisons passed using the modified runner and running legacy workers |
| Legacy image build | Succeeded; 38 dependency-free tests passed, 11 model integration tests explicitly skipped |

Numerical fixtures use public synthetic IDs defined by
`token[i] = 3 + ((i * 37 + offset) % (vocab_size - 3))`; the test source fixes offsets
and continuations. This exercises tensor equivalence without depending on natural
language quality. Greedy checks use independent feedback and record competing
top logits on divergence; neither tested sequence diverged.

The inventory contains 4,096,064 coordinator parameters, 196,992 in each of the
first two partitions and 131,328 in the third. All 4,621,376 learned parameters
are owned once and match the reference. Parameter storage pointers were checked
for unexpected aliasing. The pinned model does not tie its embedding and head.

With eight test sessions reserving 32 positions each and unequal populated prefixes,
the measured live KV storage was 147,456 bytes across stages. Closing sessions
returned live allocations and reservations to zero. These are tensor ownership
measurements, not process RSS, allocator peaks or temporary loading peaks.

## Executed commands and retained failure

From the repository root, the documented clean-artifact path succeeded:

```powershell
docker compose -f compose.pytorch.yaml build prepare
docker compose -f compose.pytorch.yaml run --rm prepare
docker compose -f compose.pytorch.yaml run --rm tests
docker compose -f compose.pytorch.yaml run --rm benchmark
```

Preparation downloaded into a new project volume. Tests and checks ran with
networking disabled and read-only artifacts/cache. The numerical observation file
was `20261014T084608947852Z-m1-validation.json`; the short CLI check was
`20261014T084622081569Z-check-pipeline.json`. Raw files remain under ignored `.lab/`;
the relevant observations are preserved in the linked sanitized JSON.

After correctness passed, two short CLI smoke workloads used the public repeated
fixture from `lab.benchmark`, 128 input tokens, eight output tokens, greedy
selection and fixed output length with EOS ignored. Warm-up was excluded.
The pipeline run completed all three requests at concurrency three. The local
reference ultimately completed all three requests at concurrency one. Their
latencies/throughput are retained only as runner diagnostics; these different
concurrency settings, tiny sample and shared CPU do not support a speed comparison.

The first local smoke attempt failed before warm-up because the offline snapshot
lookup requested every repository file, including unused README/backup files that
preparation deliberately had not fetched. The adapter now supplies the same seven
allowed files as preparation. After rebuilding, the same workload passed. The
failed `20261014T084718043698Z-bench-local.json` and successful
`20261014T084737447664Z-bench-local.json` are both retained and summarized. No failed
numerical comparison was excluded and the tolerance was never relaxed.

The modified runner's legacy check used the existing Petals image and workers with
the current `lab` and `src` directories mounted read-only. Its report is
`20261014T084657065693Z-check-pipeline.json`. A separate build tagged
`steamboat-net-lab:m1-regression` verified the updated legacy Dockerfile and its
test discovery without replacing the running baseline image or containers.

## Remaining work

M2 adds the bounded tensor protocol, operation identities and cache lifecycle.
M3 adds three worker processes/services, M4 adds scheduling across independent
requests, and M5 applies the existing network experiment design to that topology.
M1 uses one global lock and has no inter-stage communication, stage queues, leases,
RPC deadlines, compute interruption or overlap trace. Those configured future
bounds must not be mistaken for implemented mechanisms.

Loading/allocator peak memory, separate devices, GPU execution, network behavior,
energy and pooled-memory benefit were not measured. The observed numerical bound
applies to this frozen model/software/precision and these fixtures; the provisional
tolerance remains unchanged until broader repeat controls justify tightening it.
