# M4 validation: bounded concurrent coordinator

> Historical Replicant Mesh experiment, recorded before the project rename.
> Original image names, source paths and measurements are retained as evidence;
> use the [migration guide](../RENAMING.md) for current commands and names.

Date: 2026-10-15. The M4 gate passed on this laptop: the coordinator schedules
independent requests across three PyTorch worker containers, preserves reference
logits and causal order, streams tokens, and reclaims session caches. Execution
traces demonstrate overlapping model calls for different requests on different
workers. These are correctness and scheduling results, not a speedup measurement.

## Numerical and scheduling results

The final raw report is
`.lab/pytorch-results/20261015T180758317002Z-2eb4257a-m4-coordinator.json`.
It passed **144 logit comparisons**, with maximum absolute error
**3.814697265625e-6**, below the frozen `atol=1e-3, rtol=0` limit. Each comparison
covers all vocabulary logits at the final prompt position or a decode position.
Earlier M1–M3 checks retain every-prefill-position and exact-context-boundary
coverage. Reference results were computed before each cohort to avoid blocking
the scheduler's event loop during the measured overlap interval.

| Case | Requests and prompt lengths | Output evaluations | Result |
| --- | --- | ---: | --- |
| Separate single-request cohorts | One each: 1, 128, 1,024 tokens | 27 | All logits match |
| Concurrency three | 1, 128, 1,024 tokens | 27 | All logits match |
| Concurrency eight | 1,024, 128, 1,024, 7, 1,024, 128, 1,024, 1 tokens | 72 | All logits match |
| True greedy feedback | One request | 9 | Logits and generated tokens match |
| Cancellation with survivor | Cancel one stream; another completes | 9 survivor outputs | Survivor logits match; both clean up |

Each forced-feedback request evaluates nine outputs: the last prefill position
and eight decode positions with prescribed continuation tokens. Emitted tokens
are greedy choices for those contexts; the separate greedy case verifies ordinary
autoregressive feedback. The cancelled 64-output request was stopped after its
first buffered token. Its final status was `cancelled`, with confirmed cleanup.
The survivor completed all nine outputs correctly.

Every completed cohort passed causal-order and one-unresolved-call-per-worker
checks. Traces retain actual inference-thread start/end times, separate from queue
wait and RPC intervals:

| Cohort | Stage operations | Overlapping compute-span pairs | Longest pair overlap |
| --- | ---: | ---: | ---: |
| Single request, each prompt length | 27 each | 0 each | 0 ms |
| Three concurrent requests | 81 | 39 | 3.83 ms |
| Eight concurrent requests | 216 | 152 | 296.76 ms |

A pair counts only when different workers execute different requests over
intersecting time spans. These are wall-clock intervals containing real model
work, not CPU utilization, throughput or speedup estimates. No artificial
compute delay was injected into the numerical run. The final trace retained
1,066 events, with zero dropped events and zero callback errors.

All workers and the driver reported the same kernel boot identity and monotonic
clock offset. Describe samples and every recorded execution span were bracketed
by the driver's dispatch/response times. Linux time-namespace offsets are relative
to the initial namespace, so matching offsets on the same kernel boot establish
the common time base used here; namespace identifiers alone can differ in Docker.
See [Linux time_namespaces(7)](https://www.man7.org/linux/man-pages/man7/time_namespaces.7.html).
Separate physical hosts require their own synchronization and uncertainty model.

## Bounds and cleanup

The scheduler admits at most eight requests, queues at most 32 admissions and eight
operations per stage, and buffers 16 output tokens per request. Admission's
30-second deadline includes waiting, renewed preflight and all three reservations.
The generation budget is 300 seconds from submission, including admission; each
RPC is capped at 30 seconds. Worker cleanup can add up to 20 seconds before the
request result resolves. A consumer stalled for 30 seconds cancels its own request.
Renewals every 30 seconds protect queued sessions without extending hard lifetime.

Deterministic tests use smaller permitted budgets to exercise overload, FIFO order,
slow consumers, partial admission, lost Open replies, cancellation racing with
admission, worker failure, renewals, timeout and shutdown. Ambiguous Step results
are never replayed. Cleanup polls for up to 20 seconds, covering the worker's
15-second cancellation grace plus five seconds. Unconfirmed or unknown leases
return `cleanup_complete=False` and rely on bounded worker expiry.

After every remote cohort, all three workers reported zero sessions, reserved
positions, allocated cache bytes, active operations and queued operations. Final
coordinator counters were also zero, and its model thread drained successfully.
The local model executor has one thread and at most eight accepted operations;
cancelling an await does not release capacity before the underlying call finishes.
If shutdown cannot drain that thread, `close()` returns `False`; M4 cannot kill a
stuck coordinator kernel. Coordinator process supervision remains deployment work.

parameters occupy 18,485,504 bytes. Its process peak RSS was **594.70 MiB**;

CPU quotas are ceilings, not dedicated cores. Other Petals containers and a
regression container ran during parts of validation. These memory and timing
observations are not controlled performance comparisons or evidence of a
pooled-memory benefit.

## Retained iterations and remaining work

Raw reports and logs remain under ignored `.lab/pytorch-results/`; compact results,
source hashes and the successful/failed remote-run index are committed in the
summary. The first remote run completed 126 forced-feedback comparisons but failed
overlap verification because it treated distinct time-namespace IDs as distinct
clocks. The corrected implementation uses boot identity plus monotonic offset and
has explicit tests for malformed or unequal offsets. Its final remote run passed.

An earlier integration run had two teardown errors because the in-memory test
transport lacked a no-op `close()`; numerical and cancellation bodies passed.
The corrected 15-test integration run passed before the final full suite. A FIFO
test synchronization assumption was also corrected to wait for an explicit queue
event. No final test failures were excluded.

M4 provides an async coordinator library and local streaming client. M5 remains:
a standalone coordinator service, remote benchmark adapter, controlled network
shaping, and comparable latency/throughput measurements. GPU execution, separate
physical devices, WAN usefulness and pooled-memory benefit remain unverified.
RPC is plaintext and unauthenticated within this trusted private lab; automatic
replay, recovery, batching and prefill preemption are absent.
