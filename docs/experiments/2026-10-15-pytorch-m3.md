# M3 validation: three supervised PyTorch workers

> Historical Replicant Mesh experiment, recorded before the project rename.
> Original image names, source paths and measurements are retained as evidence;
> use the [migration guide](../RENAMING.md) for current commands and names.

Date: 2026-10-15. The M3 gate passed on this laptop: three separate worker
containers produced the complete-model reference logits, enforced resource bounds,
and released session caches. Process tests verified restart, stale-lease refusal,
queued renewal and independent watchdog termination. The checker calls stages
sequentially; the M4 scheduler and useful overlap remain unimplemented.

See the [machine-readable summary](2026-10-15-pytorch-m3-summary.json),
[worker guide](../PYTORCH_WORKERS.md) and [implementation plan](../PYTORCH_PIPELINE_PLAN.md).
The tested code is the working tree above `650489d06f2dd4ee96254b88e3cc5db2601be4e9`
on `codex/pytorch-pipeline-plan`. The summary records SHA-256 hashes of executable
sources, schema, tests, Compose and dependency inputs. Executable source hashes
were compared with the final built image and matched. Earlier M1/M2 reports retain
their historical source identities.

## Checks executed

```powershell
docker compose -f compose.pytorch.yaml config --quiet
docker compose -f compose.pytorch.yaml build prepare
docker compose -f compose.pytorch.yaml run --rm prepare
docker compose -f compose.pytorch.yaml run --rm tests
docker compose -f compose.pytorch.yaml up -d --wait worker-1 worker-2 worker-3
docker compose -f compose.pytorch.yaml run --rm --no-deps remote-check
```

Preparation reused and verified the existing pinned artifacts. The final full
suite passed **136 tests, zero skipped, in 56.162 seconds**. This includes the
earlier numerical/protocol tests, 15 queue tests, 10 remote admission/cleanup tests,
nine Linux process tests and five standard-library supervisor tests. Legacy-image
discovery also passed: 43 tests ran, and 93 opt-in new-runtime tests were skipped.

The process tests exercised real gRPC across child processes. They checked a real
partition's parameter residency/readiness, connection refusal, killed connections,
new boot identity after restart, stale-lease rejection, abandoned-cache expiry,
renewal during a queued wait and graceful shutdown. A blocked compute call exceeded
the actual 15-second cancellation grace and was killed/reaped by its parent.
A `SIGSTOP`-frozen child was replaced by the independent heartbeat watchdog.
Separate supervisor tests used shortened budgets to verify compute deadlines while
heartbeats continued, startup deadlines and bounded restart/reader behavior.
Fault executors exist only in the local test helper; there is no remote fault API.

## Numerical and lifecycle results

The final raw report is
`.lab/pytorch-results/20261015T075610742226Z-e154ff86-m3-remote.json`.
It passed **48 comparisons / 144 remote stage calls**, with maximum absolute logit
error **3.337860107421875e-6**, within the fixed `atol=1e-3, rtol=0` gate.

| Case | Observed result |
| --- | --- |
| 1-, 128-, 1,024-token prefill | Every vocabulary logit at every position matched tolerance |
| Eight forced decode steps per prompt | All steps matched the same-stack reference |
| Two interleaved unequal contexts | Independent caches; surviving session continued after other close |
| Exact 1,152-position context | Matched reference; overflow rejected on all three workers without changing committed position |
| Eight simultaneous session reservations | Each worker reported eight sessions and 9,216 reserved positions |
| Ninth admission | Explicit `CAPACITY_EXHAUSTED` |
| Cleanup after each scenario | Zero live sessions, reserved positions, cache bytes, active operations and queued operations |

The queue tests establish one active call, FIFO order at call boundaries, rejection
when a configured queue is full, and safe cancellation/expiry while waiting.
With eight admitted sessions and one outstanding call per session, at most seven
can wait behind the active call even though the declared queue ceiling is eight.

Two deliberate container-level negative runs were retained:

| Injection | Result | Driver duration, including setup |
| --- | --- | --- |
| Stop worker 3; run checker without Compose dependency startup | Exit 1, `EXECUTION_FAILED`, zero comparisons | 3.010 s |
| Supply worker 1's endpoint in worker 2's slot | Exit 1, `INCOMPATIBLE_MODEL` on layer assignment, zero comparisons | 2.723 s |

Worker 3 was restarted and returned healthy. Unit tests independently assert that
these preflight failures issue no OpenSession calls. The subsequent remote run
started with all workers clean and completed successfully.

## Resource observations

These are correctness-run observations, not a controlled performance comparison.
Loading spans begin after the child's Torch import. Startup peak RSS is the
inference child's `ru_maxrss` observed at readiness. Container peaks also include
the supervisor, health probes and temporary buffers.

| Worker | Resident parameters | Parameter bytes | Loading span | RSS / peak RSS at readiness | Container memory peak |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1: layers 0–2 | 196,992 | 787,968 | 2.099 s | 346.33 MiB | 471.46 MiB |
| 2: layers 3–5 | 196,992 | 787,968 | 2.048 s | 346.71 MiB | 472.38 MiB |
| 3: layers 6–7 | 131,328 | 525,312 | 2.088 s | 345.70 MiB | 471.32 MiB |

All three inspected containers were healthy with no OOM events, 3 GiB limits,
two CPU quota units and empty port bindings. The validation client's process peak
RSS was 1,157.82 MiB; it includes the complete-model control and full-prefill logits.
Its coordinator parameters account for 16,384,256 bytes; the additional complete
reference accounts for 18,485,504 bytes. Process overhead dominates this tiny model.

The eight-session check reserves full context but computes only seven prompt
positions per session. It does not measure eight fully populated 1,152-position
caches. CPU quotas are ceilings, not dedicated cores. The summary retains exact
resource observations, counts, fixtures, model hashes and cleanup diagnostics.

## Run retention and remaining work

Raw logs and uniquely named JSON reports remain under ignored
`.lab/pytorch-results/`. Both successful remote runs and the two expected negative
runs are indexed in the summary. The initial 129-test full suite passed; subsequent
review added edge-case checks and fixes before the final 136-test run. An earlier
queue-test assumption that FIFO implies increasing wait times was corrected to
check execution order and independent positive waits. No final test failures were
excluded from the recorded outcome.

This validates M3 on one shared CPU host. It does not establish GPU behavior,
useful pipeline overlap, WAN performance, pooled-memory benefit or efficiency
relative to whole-model replicas. RPC remains plaintext and unauthenticated inside
the trusted private lab. Restart invalidates requests; replay/recovery is absent.
M4 adds the coordinator scheduler and independent-request overlap. M5 adds the
new runtime's network shaping and controlled performance comparisons.
